supported host selection, approved fixture. Use a fresh English-only clean context. Codex-only
workflows must be shown in Codex, not simulated in ChatGPT. If the final Portal demands a ChatGPT
walkthrough, resolve host support before recording. Capture only the relevant app/page content.

This is coverage planning, not a claim that all scenes fit current Portal limits. Use final accepted
test wording verbatim. Prefer one continuous live sequence per supported host; disclose host switches.
Never scroll a pre-completed transcript and call it a live demonstration. Do not stitch screenshots
or hide permission prompts. No real accounts, tokens, raw machine IDs, OS desktop or notifications.

Provisional waits: catalog/search 30 seconds, one file read 30 seconds, complete conversation 90
seconds, Manual generation 5 minutes. These are observation stop points, not product SLA claims.
If exceeded, stop for diagnosis; do not repeatedly write new imports/proposals or fake the result.
On a changing conversation snapshot, allow only the Skill's one bounded restart.

Dry-run and recording each need a known mutable fixture state. Do not automatically reset completed
tasks or republish the Manual. See reviewer-fixture.md for the separate repeat-write boundary.
